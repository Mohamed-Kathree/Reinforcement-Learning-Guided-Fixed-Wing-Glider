# firmware/flight/ — ESP32 flight firmware

> **Status: Phase 1 (inner loop, no Pi). Compiles; NOT yet run on hardware.**
> The pure-C core is host-tested (`tests/test_flight_firmware.py`) against the Python
> visualiser's filter and the simulator's controller. Everything that touches the ESP32
> (SPI, data-ready interrupt, timing, PWM, ESP-NOW, I2C, UART) is unverified until the
> Phase 1 bench tests below have been run and their numbers recorded.
> **Phase 2 (the Pi policy interface) does not start until Phase 1 is verified on hardware.**

## Build and upload

```
arduino-cli compile --fqbn esp32:esp32:esp32 firmware/flight
arduino-cli upload  -p COM3 --fqbn esp32:esp32:esp32 firmware/flight
```

arduino-cli 1.6.0 ships with the Arduino IDE:
`%LOCALAPPDATA%\Programs\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe`.
Libraries: ESP32 core 3.3.x, ESP32Servo, Adafruit BMP280 (+ BusIO).

- **Confirm the COM port before every upload.** It changes between USB ports on this PC,
  and one port is marginal and causes brownouts.
- **Upload over USB with the battery OFF.** Never have USB and VIN live at the same time.
- **Close the Arduino IDE.** It holds the COM port and uploads fail while it is open.
- After editing `flighttest/config/calibration.json` or anything in `firmware/protocol/`,
  run `python -m flighttest.firmware_sync` before compiling. The test suite fails if
  you forget.

Compile measurement (19 Nov 2026): 976,383 bytes of flash (74%), 49,596 bytes of RAM (15%).

## Structure

| File | What it is |
|---|---|
| `flight.ino` | Tasks, control loop, console. |
| `config.h` | Pins (fixed), rates, failsafe setpoints, sensor settings. |
| `hw_imu.h` | ICM-20948 SPI. The bench code (verified) plus new rate/DLPF/interrupt setup (unverified). |
| `hw_sensors.h` | BMP280, sonar (interrupt-timed), NEO-6M NMEA, rail ADC. |
| `radio_link.h` | ESP-NOW `RadioLink` (Print subclass, as in the bench sketch), queue-fed. |
| `src/core/imu_frame.h` | **The** board-to-body transform. Sign defines; determinant +1 is checked at compile time. |
| `src/core/attitude.*` | 2-state Kalman per axis (port of `glider_viz.py`), accel gate, kinematics. Pure C. |
| `src/core/inner_loop.*` | The simulator's stabilisation law and safety shield, and deflection-to-µs mapping. Pure C. |
| `src/protocol/*` | Byte-identical copies of `firmware/protocol/` (generated by `firmware_sync`). |
| `src/generated/calibration_gen.h` | Generated from `calibration.json`; its hash is printed at boot. |

### Tasks

| Task | Core | Rate | Does |
|---|---|---|---|
| control (`loop()`) | 1 | data-ready, ~225 Hz | IMU read → Kalman → command frames → `rlg_safety` → inner loop → servos |
| `sensorTask` | 0 | 50 Hz | BMP280, sonar trigger/collect (20 Hz), GPS NMEA, rail ADC (5 Hz) |
| `radioTask` | 0 | queue | the **only** caller of `esp_now_send`, 15 ms settle after each |
| `consoleTask` | 0 | 100 Hz | console, 1 Hz status line, optional 5 Hz binary telemetry, optional USB stream |

The control loop never prints and never touches I2C, UART or the radio.

## Decisions

### IMU frame (decided 19 Nov 2026)

The board's raw axes are the body axes: x forward, y right, z down. All six signs are +1.
The accelerometer measures **specific force**, so:

| Attitude | Expected raw accel |
|---|---|
| level | az ≈ −1 g |
| nose up | ax > 0 |
| right wing down | ay < 0 |

The accel angles are therefore `roll = atan2(−ay, −az)` and `pitch = atan2(ax, √(ay²+az²))`.

The bench sketch's old signs (AX −1, AY −1, AZ +1) have determinant +1, but they are a
180° yaw rotation of the board, not the board-to-body transform. They inverted the gyro p
and q, which would make the damping terms anti-damp. `firmware/bench/bench.ino` now uses
the corrected signs and formulas.

`Hardware/Code/glider_viz.py` compensated for the old signs with its own negations; use
`firmware/tools/glider_viz.py` from now on. **To do before anything moves:** re-run the
bench sketch's four frame checks (level, nose up, right wing down, yaw right) with the new
firmware, and record the raw numbers. Then set `imu.verified` in the calibration file.

### Attitude

- **Filter.** Each axis has a Kalman filter with state [angle, gyro bias], in degrees,
  with Q_ANGLE 0.001, Q_BIAS 0.003 and R_MEASURE 0.03. It is a line-for-line port of the
  visualiser's filter; the host test agrees with the Python to within float32 precision.
- **Accelerometer gate.** The accel correction applies only when 0.85 g < |a| < 1.15 g.
  Otherwise the filter runs on the gyro alone.
- **Timing.** dt comes from the data-ready interrupt timestamps (GPIO 4). If no edges
  arrive at boot, the firmware falls back to 200 Hz timed polling, and the boot log and
  `report` say so.
- **Kinematics.** The flight default is Euler-angle rates (`kin` toggles it). In a banked
  turn the gate is closed (|a| ≈ 1/cos bank), so the filter runs on the gyro for the whole
  turn. Integrating body rates there, as the visualiser does, drifts by tens of degrees.
  The host test shows this.
- **Yaw is not referenced.** There is no magnetometer, so yaw is integrated gyro and
  drifts. The status line labels it "(drift)".

### Barometer, sonar and GPS

- **Barometer.** The ground pressure reference is **never captured at boot.** It is
  captured when FLIGHT is armed, as the mean of the last 0.5 s of pressure. It is not
  re-captured while the safety layer says the aircraft is airborne. FLIGHT arming is
  refused until `baro.warmup_s` (120 s) has passed since boot. Before capture, altitude
  is NaN, so it does not vote "airborne".
- **Baro-to-sonar handoff: there is none in the firmware.** The simulator gives the
  policy both channels as they are: `baro_alt` (obs[7]) and `lidar_agl` with
  `lidar_valid` (obs[9–10], valid below 4.5 m, flare only). The firmware therefore
  forwards both raw, with sonar validity gated at 4.5 m to match the simulator. Nothing
  blends them, so there is no new handoff to model in the simulator. The ESP32 uses the
  barometer only for the safety layer's airborne vote. If a blended altitude is ever
  wanted, it has to be added to the simulator first.
- **GPS** (NEO-6M, NMEA, 1 Hz). GGA gives fix, satellites and position; RMC gives speed
  and course, from which vn and ve are computed. GPS altitude is never used for control.

### Failsafe

- **Trigger.** In FLIGHT, no Pi setpoints for 150 ms latches failsafe (`rlg_safety`).
  It needs 5 fresh setpoints in a row to clear.
- **Phase 1 behaviour.** There is no Pi in Phase 1, so FLIGHT always flies the failsafe
  setpoints: roll 0°, pitch −2° (`config.h`).
- **The −2° pitch is a first guess.** The simulator's trimmed glide pitch is about +0.7°;
  −2° trades some glide ratio for stall margin. Tune it in simulation and on hardware.
- **The ESP-NOW link has no effect on flight.** Losing it in FLIGHT changes nothing.

### Arming preconditions (firmware, on top of `rlg_safety`)

FLIGHT arming is refused when any of these holds. The refusal is shown as `cmd=refused:…`.

- the IMU failed WHO_AM_I;
- the barometer warm-up has not finished;
- the calibration file says the servos or the IMU frame are unmeasured, unless `uncal`
  was typed this boot (bench only; surface directions are then unverified).

## Console (USB, or radio through the ground station)

| Command | Effect |
|---|---|
| `help` | List the commands. |
| `arm` | Queues 5 FLIGHT frames (`rlg_safety`'s arming rule) and flies the failsafe glide. |
| `disarm` | Disarms; the surfaces go to neutral. |
| `uncal` | Allows FLIGHT arming with unmeasured calibration until reboot. Bench only. |
| `tlm` | Turns 5 Hz binary `rlg_telemetry_t` over the radio on or off. Default off. |
| `stream` (or a bare `8`) | Turns the USB stream for the visualiser on or off: `D,t,ax,ay,az,gx,gy,gz` (raw body counts) plus `E,t,roll,pitch,gate`, about 112 Hz. USB only, never radio. |
| `kin` | Toggles Euler kinematics. Off integrates body rates, like `glider_viz.py`. |
| `report` | Prints the full measurement report (`R` lines). |

**Status line.** One line per second, beginning with `S`. Fields:

- mode;
- roll, pitch and yaw;
- |a| and whether the accel was used;
- loop rate;
- dt min/mean/max in µs;
- compute time, mean and max in µs;
- percentage of samples gated;
- data-ready timeouts (`tmo`) and missed samples (`ovr`);
- shield activations;
- barometer, sonar, GPS and rail;
- the four servo µs values;
- the last command result.

## Phase 1 bench test plan

Record the number in every row, not just pass or fail. USB tests run with the battery
**OFF**. Servo tests run on battery with USB **unplugged**, using the console over the
radio.

> **Never arm (FLIGHT, or anything else that moves a servo) with USB plugged in.**
> USB 5 V back-feeds the board's VCC rail through the dev board's VIN diode, so the
> servos are powered from the PC port even with the battery disconnected. On 19 Nov 2026,
> arming FLIGHT on USB moved a servo, collapsed the supply, and left the ESP32 dead (no
> response even to a hardware reset) until USB was unplugged. On USB, stay DISARMED;
> the servos only go to neutral once at boot. A hardware fix (a diode or jumper in the
> VCC→VIN path, or unplugging the servo leads on USB) is an open option.

**First run, 19 Nov 2026 (USB, battery off, disarmed):**
- WHO_AM_I 0xEA; data-ready 230 Hz on interrupt timing; MAC F8:B3:B7:30:33:40.
- Loop 228 Hz, dt mean 4390 µs (min/max typically ±0.5 ms, worst seen 3066/5714 µs),
  compute 165–174 µs mean, of which about 165 µs is the IMU SPI read. No timeouts or
  missed samples.
- Level, raw accel (+0.002, −0.022, −1.080) g, so az sign ✓. |a| reads 1.07–1.08 g: an
  accelerometer scale/offset error to measure (six-position test), still inside the
  0.85–1.15 gate. Gyro bias at rest (+1.0, −0.5, 0.0) °/s.
- BMP280 ok; NMEA parsing ok (123 sentences, 0 bad checksums, no fix indoors); rail pin
  0.142 V on USB (divider not fitted, reported invalid).
- `ledcWrite()` blocks about 10 ms per servo, so servo output runs in its own 50 Hz task.
- Armed FLIGHT with `srv off` ran normally: failsafe engaged, barometer reference
  captured, surface commands correct in sign. With `srv on`, see the warning above.

### Servo calibration (joint session)

A wrong servo direction is a **silent inversion**: the loop then drives the aircraft
away from level. Each servo's `direction` in `calibration.json` is defined against the
**simulator's** positive deflection:

| Surface | Simulator positive | Set `direction` so that a positive command… |
|---|---|---|
| aileron L (servo 0) | rolls right (Cl_da +0.15) | moves the left aileron trailing edge **down** |
| aileron R (servo 1) | rolls right | moves the right aileron trailing edge **up** |
| elevator (servo 2) | pitches nose down (Cm_de < 0) | moves the elevator trailing edge **down** |
| rudder (servo 3) | yaws nose left (Cn_dr −0.05) | moves the rudder trailing edge **left** |

Both ailerons get the same signed command, so each aileron's `direction` alone sets which
way its surface moves.

For each servo, measure and record:

- `neutral_us`: surface aligned;
- `min_us` and `max_us`: the end stops minus a margin; no binding;
- `us_full_deflection`: the µs offset that gives the simulator's maximum (25° aileron,
  20° elevator, 25° rudder), measured with a protractor or deflection gauge.

Enter them through the dashboard's Ground Station page, or edit the JSON. Set `measured`,
run `python -m flighttest.firmware_sync`, rebuild and re-flash, then repeat test 13.

## Known issues (open)

- **The ground station bridge sends one byte per ESP-NOW packet** from USB. Text console
  commands work, as in the bench sketch. Binary command frames from the dashboard arrive
  split up, so the firmware treats them as text. Fix the bridge before the dashboard
  drives BENCH or REPLAY over the air.
- **The bench sketch** still has `delay(8)` after `esp_now_send`. The flight firmware uses
  the 15 ms in the brief.
- **ICM-20948 rate and interrupt configuration is new code.** Test 1 shows whether it
  took effect.
- **Phase 2 contract mismatches.** These must be resolved before the Pi interface is
  written; see `firmware/README.md`.
